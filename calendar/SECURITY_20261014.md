# Calendar write-path security — 14 October 2026

Calendar 1.536 follows the native viewing migration. This change is tested on
local Chisimba with PHP 8.5 and PDO MySQL; it is not a production deployment.

## Event boundary

The editor uses canonical login, personal ownership, persisted course instructor
membership and site administrator checks. It checks every row in a multiday
series again during the write. Personal events belong to their owner; course
and site events require their respective roles. Module-generated events remain
managed by their source module. Unsupported legacy workgroup events are read-only
here; no permissive fallback is provided.

Writes require POST and the shared login-bound CSRF service. A session-issued
creation identifier prevents arbitrary creation IDs and duplicate creation on
replay. Creation rejects a changed current course. Existing scope, original author
and first-entry date cannot be moved through the form.

The dbTable repository uses prepared operations, a shared database lock and
savepoint transactions. Updates retain the series root ID and retained child IDs.
Shrinking a series moves removed children's attachment references to the retained
root. Revisions cover all series rows and attachment links. Stale edits fail;
partial writes roll back. Delete GET only renders a confirmation; confirmed POST
checks the same permissions, token and revision before deleting records.

The form uses native dates/times, the shared rich editor/sanitiser, HTTP(S) URL
validation, contextual Help and shared skin forms. Failed submissions retain text
and the original revision, issue a fresh token, and explain how to inspect saved
state without silently replaying an uncertain operation. Saved changes have a
visible status message. Dates/times use the shared responsive two-column grid.

## Retired attachment boundary

The old form's attachment iframe/upload path was already disabled. Its controller
routes were still reachable and its model performed unsafe raw filesystem work.
Temporary frame, upload, download and delete routes now return HTTP 410. The
compatibility model lists no raw paths and rejects all writes/transfers; it no
longer performs filesystem operations. Its obsolete iframe template is removed.
The shared calendarbase consumer receives an empty legacy file list safely.

Existing file bytes are never deleted or moved by this change. Event deletion
removes its database attachment links; normal updates preserve them. Use File
Manager links with normal access checks for new supporting material. This is not
a replacement upload implementation or a migration of historical file bytes.

Local inventory found zero attachment rows and no legacy attachment directory.
**Before production deployment, inventory historical attachment rows, physical
files and any public/static aliases on each target site.** Retiring a PHP route
cannot revoke a direct web-server file URL. Preserve and move any such files out
of public reach through a separately reviewed migration before releasing there.

## Validation

- `native_calendar_test.php`: escaping, disclosures, category classes, ordering,
  repeat/empty rendering.
- `native_calendar_client_test.js`: native grid/list filtering and isolation.
- `native_calendar_pdo_test.php`: category visibility and outsider exclusion.
- `secure_calendar_routes_test.php`: anonymous/method rejection, confirmation-only
  GET, retired attachment methods with traversal-like inputs, server-issued creation
  tickets, rejected CSRF/stale/uncertain submissions retain drafts and revisions.
- `secure_calendar_pdo_test.php`: actual PDO create/update/delete for personal,
  course and site scope; ownership/role rejection and revocation; CSRF/method
  guards; duplicate/stale submissions; sanitisation; stable IDs; attachment-link
  retention on shrink; injected second-write failure and complete rollback.
  Actor/CSRF adapters are synthetic; browser saves exercise the real session and
  CSRF composition. All database fixtures roll back.
- Chrome on local Chisimba: create, rich text, invalid-date draft recovery,
  extend/shrink, stable root ID, visible save confirmation, delete confirmation
  and Cancel, quick/full Help and Escape, desktop and 390px viewport. The exact
  disposable event was removed afterwards; the original course session stayed
  unchanged. Download route visibly reports retirement and logs HTTP 410.
- PHP 8.5 syntax and whitespace checks pass. No PHP warning, notice, deprecation
  or fatal in the final 30-minute test window. Browser console entries were from
  the installed Grammarly extension, not Calendar.

PDO tests run from the Chisimba root with `CHISIMBA_CALENDAR_TEST=1`; never point
these fixtures at production. Normal Module Catalogue registration/hooks updated
local Calendar to 1.536; no schema change is needed.

## Boundaries

This hardens Calendar's own editor and raw attachment API. It does not certify
all other modules that write through calendarbase. The legacy iCalendar exporter
was not modernised in this change; its old time parsing needs a compatibility
pass. Global skin jQuery remains for other consumers.
